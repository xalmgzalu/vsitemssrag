# Telegram-пилот VistaSport RAG

TASK-3 реализован **7 ноября 2026**. Бот использует aiogram 3.x
(в `uv.lock` закреплён 3.31.0) и общий `rag.service.ask_catalog`, который
вызывает CLI `ask`. Генератор, бюджетный фильтр, evidence-renderer,
валидатор и безопасный fallback сохранены.

## Локальный запуск

Из корня проекта:

```bash
uv sync
uv run vsitemssrag bot run --check
uv run vsitemssrag bot run
```

Остановка — Ctrl+C. Для одного токена должен работать один polling-процесс.
Запуск не удаляет webhook и не сбрасывает ожидающие updates; если webhook
уже настроен, программа явно сообщает об этом и не начинает polling.
Механизм описан в [документации aiogram](https://docs.aiogram.dev/en/latest/dispatcher/long_polling.html).

Настройки хранятся только в локальном `.env`, пример — в `.env.example`:

```env
TELEGRAM_BOT_TOKEN=
GEMINI_API_KEY=
DATABASE_URL=
RAG_EVIDENCE_FILE=data/exports/review_enrichment_pilot_v2.json
```

Токен создаётся через @BotFather и не передаётся в аргументах команды.
`--check` проверяет конфигурацию, Telegram getMe и отсутствие webhook, затем
закрывает соединение. Токен не печатается; известные секреты редактируются
в логах, в том числе в traceback сторонних библиотек.

Каталог/embeddings должны быть подготовлены по README. Бот по умолчанию
требует существующий пилот v2 с matched-агрегатами: он не переключается молча
на baseline, для которого гейт качества не подтверждён. В новом клоне этот
JSON отсутствует, потому что генерируемые данные исключены из Git. Укажите
свой файл через `RAG_EVIDENCE_FILE` или `--evidence-file`; новый сбор пилота
выполняется командой `uv run vsitemssrag enrich-reviews` и не считается
продолжением исторического A/B.

Дополнительные параметры:

```bash
uv run vsitemssrag bot run \
  --evidence-file data/exports/review_enrichment_pilot_v2.json \
  --feedback-db data/bot/feedback.sqlite3 \
  --timeout 30 \
  --max-concurrent 2
```

Timeout относится к отдельным RAG-запросам; повторы могут увеличить общее
время ответа. Параллельно выполняется до двух подборов; повтор того же
пользователя во время подбора и запрос при полной загрузке получают понятное
сообщение. Синхронные Gemini/PostgreSQL вызовы выполняются через
`asyncio.to_thread`, поэтому `/start` и feedback не ждут завершения RAG.

## Пользовательский сценарий

1. Открыть [@vistasportassistant_bot](https://t.me/vistasportassistant_bot).
2. Отправить `/start` или `/help`.
3. Написать, например: «Я новичок, бюджет до 6000 ₽, хочу контрольное основание».
4. Открыть выбранный товар инлайн-кнопкой с тем же номером `[n]`, что в тексте.
5. Нажать 👍 или 👎 под последней частью ответа.

Подбираются основания. Каждый запрос независим: история предыдущих сообщений
не передаётся в RAG. После уточнения нужно отправить полный запрос со всеми
критериями. Накладки и расчёт полного комплекта ещё не реализованы.

HTML из ответа экранируется; поддерживается простой Markdown-bold.
Длинный текст делится с учётом UTF-16 и emoji, без потери исходного текста.
Кнопки находятся только под последней частью ответа. При ошибке HTML-парсинга
Telegram используется plain text. Кнопки товаров строятся по процитированным
DB-источникам, только для HTTPS URL каталога VistaSport; ссылки из свободного
текста модели не превращаются в кнопки.

Общий запрос получает уточнение без обращения к Gemini/БД; пустой бюджетный
результат — детерминированный отказ без генерации и без кнопок дорогих товаров.
Ошибка RAG/таймаут даёт сообщение без внутренних инструкций или секретов.

## Фидбек и локальные данные

`data/bot/feedback.sqlite3` и WAL-файлы исключены из Git.

- `responses`: вопрос, итоговый ответ, origin, процитированные товары,
  автор, чат, ID последнего сообщения и время UTC.
- `feedback`: одна актуальная оценка на ответ, значение +1 или -1 и время UTC.
  Повтор той же оценки не увеличивает счётчик; смена оценки обновляет запись.

Callback проверяет автора, чат и исходное сообщение. Пересланная или поддельная
кнопка не позволяет оценить чужой ответ. Оценки переживают перезапуск процесса;
они не меняют prompt и не обучают модель автоматически.

Для метрик доставленных ответов отбирайте `responses.message_id IS NOT NULL`.
Уточнения и fallback различаются по `origin` и не должны смешиваться с
успешными свободными рекомендациями модели.
