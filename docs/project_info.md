# Архитектура VistaSport RAG

Актуализировано **7 ноября 2026** по локальному коду. Текущее состояние,
результаты проверок и следующие задачи — в [CURRENT_STATE.md](CURRENT_STATE.md).

## Назначение

Проект собирает основания для настольного тенниса из каталога VistaSport,
нормализует карточки, сохраняет их в JSON или Supabase PostgreSQL и подбирает
товары через semantic search и RAG. Интерфейс — CLI. Внешние отзывы добавляются
экспериментально через `--evidence-file`.

## Слои приложения

- `scraping.vistasport`: HTTP-сессия, паузы и повторы, пагинация, ProductGroup
  JSON-LD, варианты и HTML-описания. Результат — общий тип `Product`.
- `storage.postgres`: SQL-миграции, идемпотентный UPSERT, история обходов,
  деактивация пропавших товаров после полного успешного прохода, `content_hash`,
  хранение embeddings и поиск через `match_products`.
- `embeddings`: построение документов, клиент Gemini и pipeline обновления
  изменённых товаров. Модель `gemini-embedding-2`, 768 измерений. Цена и наличие
  не включаются в embedding-текст.
- `enrichment`: сопоставление с BladeRubber.net и агрегирование отзывов без
  сохранения исходных текстов. Для длинных шипов — эвристические категории
  `positive`, `negative`, `unclear`; для остальных свойств — keyword-сигналы.
- `rag.constraints`: извлечение бюджета и эвристика общего запроса, которому
  нужен фиксированный уточняющий вопрос.
- `rag.context`: изолированный prompt с каталогом и опциональными агрегатами;
  числовые evidence-фразы формируются кодом.
- `rag.gemini` и `rag.advisor`: клиент генерации и общий цикл «генерация →
  validation → исправляющая попытка», до трёх попыток. По умолчанию используется
  `gemini-3.5-flash-lite`; после исчерпания попыток возвращается ошибка.
- `rag.validation`: детерминированная проверка ссылок, числовых evidence-фраз
  и некоторых неподтверждённых выводов. Это эвристический фильтр, а не полная
  проверка истинности всех утверждений.
- `rag.evaluation` и `evals/`: grader пяти сценариев, A/B-runner с атомарным
  checkpoint и пересчёт сохранённых ответов без API.
- `cli`: команды `scrape`, `db`, `embed`, `search`, `ask`, `enrich-reviews`;
  связывание компонентов, конфигурация и вывод прогресса.

`settings` загружает секреты из корневого `.env`; `models` содержит общие
типы `Product` и `ProductVariant`. SQL-миграции входят в Python-пакет.

## Поток данных

```text
VistaSport → scraping → Product → JSON / PostgreSQL
                                           │
                                    embedding pipeline
                                           │
                                  product_embeddings
                                           │
Вопрос → проверка уточнения → query embedding → pgvector retrieval
             │                                      │
             ▼                                      ▼
     фиксированный вопрос                 кандидаты и бюджетный фильтр
                                                    │
BladeRubber → enrichment → matched-агрегаты ──────────┤ (опционально)
                                                    ▼
                                           prompt → Gemini
                                                    │
                                    validation / исправляющая попытка
                                                    │
                                                    ▼
                                     ответ + источники / ошибка RAG
```

Общий запрос, распознанный CLI, завершается до обращений к БД и Gemini.
Для конкретного запроса БД закрывается до генерации. Подтверждённые агрегаты
добавляются в контекст только для `matched`-товаров. Готовые evidence-фразы
модель пока переносит в свободный ответ сама — на этом этапе последний A/B
прогон v4 остановился из-за ошибки validation.

Текущее ограничение бюджетного фильтра: если в retrieval нет ни одного
кандидата в бюджете, CLI оставляет исходных кандидатов. Это требует исправления
до заявления о строгой гарантии бюджета.

## Таблицы

- `products` — нормализованная карточка и характеристики JSONB.
- `product_variants` — варианты ручек, SKU, цены и наличие.
- `scrape_runs` — состояние и метрики каждого запуска.
- `product_embeddings` — embedding, модель, документ и `content_hash` товара;
  pgvector, cosine distance и HNSW-индекс.
- `app_private.schema_migrations` — применённые версии схемы.

На таблицах публичной схемы включён RLS без клиентских политик. Доступ приложения
выполняется серверным PostgreSQL-подключением из `DATABASE_URL`.
