## Где остановились

TASK-1: общий бюджетный фильтр для CLI и eval-runner. Пустая бюджетная выборка
получает точное сообщение об отсутствии найденных вариантов без генерации;
дорогие и неизвестные цены не подставляются. Проверены CLI, runner и краевые
случаи цен, включая равенство бюджету и нечисловые/бесконечные значения.

TASK-2: модель получает качественные сигналы, код добавляет точные агрегаты и
источники только для процитированных товаров. Проверяется исходный текст и
весь собранный ответ. Отклонения сохраняются в локальном JSONL. После трёх
отказов применяется безопасный каталоговый fallback с отдельным происхождением.
Для long-pips нужен явный DEF/DEF+; если запрошена мягкость, её нельзя пропустить.

Аудит выполнен агентом-разработчиком: он не независимый, не слепой и не является
человеческим/пользовательским аудитом. В v6: 23 принятых текста Gemini,

14 отклонённых попыток записаны в локальный лог. Эти метрики не описывают
качество только свободных генераций модели.

Оставшиеся два enriched-провала v6 — неподтверждённая большая мощность и
небезопасное сравнение цифровых индексов разных брендов. Поэтому нулевая метрика
межбрендовых сравнений из Vision пока не подтверждена. Baseline также допускает
неподтверждённые свойства и неполные объяснения. Гейт 12/15 не означает полной
готовности всех режимов к запуску.

## Что уже реализовано

### Каталог, хранение и поиск

- Парсер каталога оснований VistaSport: пагинация, паузы, повторы временных
  ошибок, JSON-LD `ProductGroup`, варианты и HTML-описания.
- Хранилища `json`, `postgres`, `both`; идемпотентная запись товаров и вариантов,
  история `scrape_runs`, деактивация пропавших позиций только после полного
  успешного обхода.
- SQL-миграции в пакете, RLS на публичных таблицах, `content_hash` для обновлений.
- Embeddings: `gemini-embedding-2`, размерность 768; pgvector, cosine distance,
  HNSW и функция `public.match_products`. Команды `embed` и `search`.
- Цена и наличие берутся из полей БД и не входят в embedding-текст.

### RAG и проверки ответа

- Команда `ask`, модель генерации по умолчанию `gemini-3.5-flash-lite`, до шести
  товаров в контексте. CLI печатает ссылки на каталог и, при наличии, отзывы.
- Распознаваемый общий запрос без критериев получает фиксированный уточняющий
  вопрос без рекомендаций; CLI завершает его до обращений к БД и Gemini.
  Распознавание основано на эвристике, а не на полном понимании любого запроса.
- Общий `generate_advisor_answer` для CLI и eval проверяет ответ и делает до
  трёх generation-попыток с обратной связью от валидатора. При исчерпании
  попыток формируется безопасный резервный ответ из каталога и агрегатов,
  без отклонённого текста модели. Для long-pips выбираются только явные
  DEF/DEF+. Если даже резервный текст не проходит validation, возвращается
  ошибка. Ошибки API обрабатываются отдельно.
- `VALIDATOR_VERSION = 7`: проверка ссылок, чисел evidence в привязке к товару
  и сигналу, опасных сравнений и некоторых неподтверждённых выводов.
- `GRADER_VERSION = 7`: детерминированные проверки пяти сценариев. Лексические
  проверки не заменяют ручной аудит всех фактических утверждений.
- Каталог и отзывы в prompt считаются недоверенными данными; инструкция
  запрещает прямое сравнение числовых шкал разных брендов.

Явный верхний бюджет извлекается кодом. Если подходящих кандидатов нет, CLI
возвращает сообщение «По вашему запросу не найдены варианты до X ₽» без
генерации. Речь идёт о поисковой выборке, а не об отсутствии товаров во всём
каталоге. Проверены пустая и смешанная выборки, неизвестная цена, точное
равенство бюджету, порядок/лимит, нечисловые и бесконечные значения.

### Внешние отзывы

- Источник пилота — публичные sitemap и JSON-LD BladeRubber.net, пауза 1,5 с.
  TableTennisDaily ранее отвечал `403` и не используется в регулярном pipeline.
- Полные тексты не сохраняются: только агрегаты, сигналы и ссылки.
- Текущий файл: `data/exports/review_enrichment_pilot_v2.json`; 20 товаров,
  18 matched (90%), 1 candidate, 1 unmatched, 15 matched с отзывами, 59 отзывов.
- Для длинных шипов добавлена эвристическая классификация `positive`, `negative`,
  `unclear`. В текущем пилоте: отрицательный сигнал у 1 товара, неоднозначный —
  у 2, положительный не зафиксирован. Это не доказательство несовместимости.
- В RAG допускаются только `matched`; в prompt идут только качественные
  `signals`, без числовой статистики. После выбора моделью код добавляет
  отдельный блок точных агрегатов и URL источников для процитированных товаров.
- Модельная статистика отзывов (N из M, проценты, дроби, словесная частота)
  отклоняется отдельно. Итоговые числа проверяются по товару и сигналу.
