## Где остановились

Основа CLI-консультанта работает: каталог VistaSport → PostgreSQL/Supabase →
embeddings и поиск через pgvector → ответ Gemini с источниками. Сейчас задача —
стабилизировать ответы с агрегатами внешних отзывов. Enrichment остаётся
экспериментальным и включается через `--evidence-file`.

Последний прогон `data/exports/enrichment_ab_results_v4.json` имеет статус
`paused`: сохранено 7 из 30 ответов (4 baseline и 3 enriched). Все семь прошли
автоматический grader, но это неполная выборка, а не итог эксперимента.
Последний checkpoint обновлён 30 августа в 19:32:55 UTC (22:32:55 МСК).

Причина остановки:

> GeminiGenerationError: ответ отклонён grounding-валидатором: числовая evidence-фраза должна содержать один товар, один сигнал и одну пару N из M

Остановка произошла в сценарии `fast_attack_carbon`, на первом enriched-ответе,
после исчерпания попыток исправить ответ. Отклонённый ответ в checkpoint не
сохраняется; по `last_error` нельзя установить его точный текст или доказать
ошибку в самих числах.

## Что уже реализовано

### Каталог, хранение и поиск

- Парсер каталога оснований VistaSport: пагинация, паузы, повторы временных
  ошибок, JSON-LD `ProductGroup`, варианты и HTML-описания.
- Хранилища `json`, `postgres`, `both`; идемпотентная запись товаров и вариантов,
  история `scrape_runs`, деактивация пропавших позиций только после полного
  успешного обхода.
- SQL-миграции в пакете, RLS на публичных таблицах, `content_hash` для обновлений.
- Embeddings: `gemini-embedding-2`, размерность 768; pgvector, cosine distance,
  HNSW и функция `public.match_products`. Команды `embed` и `search`.
- Цена и наличие берутся из полей БД и не входят в embedding-текст.

### RAG и проверки ответа

- Команда `ask`, модель генерации по умолчанию `gemini-3.5-flash-lite`, до шести
  товаров в контексте. CLI печатает ссылки на каталог и, при наличии, отзывы.
- Распознаваемый общий запрос без критериев получает фиксированный уточняющий
  вопрос без рекомендаций; CLI завершает его до обращений к БД и Gemini.
  Распознавание основано на эвристике, а не на полном понимании любого запроса.
- Общий `generate_advisor_answer` для CLI и eval проверяет ответ и делает до
  трёх generation-попыток с обратной связью от валидатора. При исчерпании
  попыток возвращается ошибка, отклонённый ответ пользователю не выдаётся.
- `VALIDATOR_VERSION = 2`: проверка ссылок, чисел evidence в привязке к товару
  и сигналу, опасных сравнений и некоторых неподтверждённых выводов.
- `GRADER_VERSION = 3`: детерминированные проверки пяти сценариев. Лексические
  проверки не заменяют ручной аудит всех фактических утверждений.
- Каталог и отзывы в prompt считаются недоверенными данными; инструкция
  запрещает прямое сравнение числовых шкал разных брендов.

Явный бюджет извлекается кодом. Ограничение текущей реализации: если в retrieval
нет ни одного товара в бюджете, CLI сохраняет исходных кандидатов. Поэтому
строгое соблюдение бюджета для всех запросов пока не гарантировано.

### Внешние отзывы

- Источник пилота — публичные sitemap и JSON-LD BladeRubber.net, пауза 1,5 с.
  TableTennisDaily ранее отвечал `403` и не используется в регулярном pipeline.
- Полные тексты не сохраняются: только агрегаты, сигналы и ссылки.
- Текущий файл: `data/exports/review_enrichment_pilot_v2.json`; 20 товаров,
  18 matched (90%), 1 candidate, 1 unmatched, 15 matched с отзывами, 59 отзывов.
- Для длинных шипов добавлена эвристическая классификация `positive`, `negative`,
  `unclear`. В текущем пилоте: отрицательный сигнал у 1 товара, неоднозначный —
  у 2, положительный не зафиксирован. Это не доказательство несовместимости.
- В RAG допускаются только `matched`; фразы «N из M» формируются кодом и
  передаются в `summary_lines`. Модель пока сама включает их в ответ, поэтому
  даже готовые фразы могут быть изменены или объединены некорректно.

Локальные проверки без внешних запросов:

```bash
git status -sb
uv run python -m unittest discover -s tests -q
```

Последняя команда проверяет только фиксированный уточняющий вопрос. Проверка
актуальной БД и реальный RAG-запрос выполняются отдельно:

```bash

uv run vsitemssrag db status

  --evidence-file data/exports/review_enrichment_pilot_v2.json
```
