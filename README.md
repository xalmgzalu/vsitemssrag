# VistaSport RAG

Локальный RAG-проект для поиска и подбора инвентаря для настольного тенниса.

TASK-1/TASK-2 реализованы: бюджетный фильтр исправлен, агрегаты отзывов
собираются кодом, отклонённые ответы логируются локально. После отрицательного
v5 (11/15 enriched по аудиту) отдельный v6 достиг заданного порога: **13/15**,
без ошибок чисел evidence и обещаний совместимости. Аудит выполнен агентом,
не независимым проверяющим; baseline и отдельные сравнительные формулировки
ещё требуют доработки. Enrichment остаётся экспериментальным.

Состояние и следующие шаги — в [CURRENT_STATE.md](docs/CURRENT_STATE.md),
построчные отчёты — [v5](docs/AB_V5_AUDIT.md) и [v6](docs/AB_V6_AUDIT.md).

Для продуктового контекста начните с [PRODUCT_BRIEF.md](docs/PRODUCT_BRIEF.md),
[PRODUCT_VISION.md](docs/PRODUCT_VISION.md) и инженерного бэклога [SPRINT_1_BACKLOG.md](docs/SPRINT_1_BACKLOG.md):
цель, границы MVP, приоритеты, критерии приёмки и открытые решения владельца.

## Установка

Установите `uv` на macOS и синхронизируйте окружение:

```bash
brew install uv
uv sync
```

`uv` создаст `.venv`, установит проект в editable-режиме и зафиксированные в
`uv.lock` зависимости.

## Команды

Все операции доступны через единый CLI:

```bash
uv run vsitemssrag --help
```

Проверка подключения и управление схемой PostgreSQL:

```bash
uv run vsitemssrag db check
uv run vsitemssrag db migrate
uv run vsitemssrag db status
```

Безопасный пробный запуск парсера ограничен десятью товарами. По умолчанию JSON
будет записан в `data/exports/products.json`:

```bash
uv run vsitemssrag scrape
```

Потоковая запись трёх товаров напрямую в Supabase PostgreSQL:

```bash
uv run vsitemssrag scrape --storage postgres --limit 3
```

Полный проход без создания JSON:

```bash
uv run vsitemssrag scrape --storage postgres --limit 0
```

Одновременная запись в PostgreSQL и отладочный JSON:

```bash
uv run vsitemssrag scrape --storage both --limit 10
```

Парсер делает паузу 1,5 секунды между запросами, повторяет временно неудачные
запросы и сохраняет каждую карточку сразу после обработки. Ограниченный или
частично неудачный запуск не помечает остальные товары отсутствующими. Только
полностью успешный запуск с `--limit 0` помечает пропавшие товары недоступными.

## Конфигурация

Секреты хранятся в `.env`, который исключён из Git:

```env
GEMINI_API_KEY=
DATABASE_URL=postgresql://USER:PASSWORD@HOST:PORT/postgres
```

## Telegram-бот

TASK-3 реализован. Локальный пилот: [@vistasportassistant_bot](https://t.me/vistasportassistant_bot).
Добавьте `TELEGRAM_BOT_TOKEN` в `.env` и используйте подготовленный каталог
с evidence-пилотом v2:

```bash
uv run vsitemssrag bot run --check
uv run vsitemssrag bot run
```

Бот принимает текстовые запросы, использует тот же RAG-сервис, что CLI,
показывает инлайн-ссылки только на выбранные товары и сохраняет 👍/👎 локально.
Каждый запрос независим; это подбор оснований без памяти диалога.
Подготовка данных, параметры и проверка — в
[TELEGRAM_BOT.md](docs/TELEGRAM_BOT.md).

После TASK-3.2 общий RAG использует расширенный пул, строгий бюджет и
детерминированный реренкинг по приоритетам PO. Справка материалов добавляется
только при явно указанном составе/положении слоёв. Реализация и проверки —
[HYBRID_RETRIEVAL.md](docs/HYBRID_RETRIEVAL.md).

## Векторное хранилище

Команда миграции включает расширение `pgvector` в Supabase и создаёт таблицу
`public.product_embeddings`:

```bash
uv run vsitemssrag db migrate
```

Для embeddings выбрана модель `gemini-embedding-2` с размерностью 768. Таблица
хранит один актуальный embedding на товар вместе с моделью, исходным текстом и
`content_hash`. Поиск использует cosine distance через HNSW-индекс и серверную
функцию `public.match_products`. На таблице включён RLS без клиентских политик.

В новой БД после миграции таблица пуста. Её заполняет отдельный embedding
pipeline, обрабатывающий только товары с новым или изменившимся `content_hash`.

Создайте ключ на странице [Google AI Studio API Keys](https://aistudio.google.com/app/apikey)
и сохраните его только в локальном `.env`:

```env
GEMINI_API_KEY=your-key
```

Безопасный пробный запуск обрабатывает три товара:

```bash
uv run vsitemssrag embed
uv run vsitemssrag search "контрольное основание для новичка"
```

После проверки качества можно обработать все ожидающие товары:

```bash
uv run vsitemssrag embed --limit 0
```

Цена и наличие не входят в embedding-текст: semantic search отвечает за смысл,
а изменчивые и точные ограничения применяются к актуальным полям PostgreSQL.

## RAG-консультант

Команда `ask` сначала находит подходящие товары через pgvector, затем передаёт
их актуальные цены и характеристики в Gemini для grounded-ответа:

```bash
uv run vsitemssrag ask \
  "Я новичок, бюджет до 6000 ₽, хочу максимально контрольное основание"
```

По умолчанию в коде для генерации выбрана модель
`gemini-3.5-flash-lite`. При необходимости её можно заменить без изменения
кода:

```env
GEMINI_GENERATION_MODEL=gemini-3.5-flash-lite
```

Явный верхний бюджет (`до 6000`, `не дороже 6 тысяч`, `максимум 6000`) сначала
применяется кодом к точной цене из PostgreSQL. Gemini получает только
товары с известной конечной положительной ценой в пределах бюджета. Если таких
товаров в поисковой выборке нет, CLI формирует сообщение «По вашему запросу
не найдены варианты до X ₽» без генерации и без списка дорогих товаров. Это
сообщение относится к поисковой выборке, а не ко всему каталогу. После ответа CLI
детерминированно печатает товары и URL, соответствующие ссылкам `[1]`, `[2]`.

Распознаваемый общий запрос вроде «Посоветуй хорошее основание» получает
фиксированный вопрос об уровне, стиле и бюджете без рекомендаций и без
обращений к БД или Gemini. Для конкретного запроса общий generation-проход
проверяет ссылки, числовые evidence-фразы и некоторые неподтверждённые выводы.
После трёх отклонений код формирует безопасный резервный ответ из каталога
и агрегатов; если и он не проходит проверку, возвращается ошибка RAG. Эти эвристические
проверки не заменяют ручную оценку качества.

Отклонённые ответы, собранный итоговый текст и точные причины ошибок
записываются локально в `data/exports/rag_validation_rejections.jsonl`
(исключён из Git).

Небольшой регрессионный набор пользовательских сценариев хранится в
`evals/rag_cases.json`; инструкция по расширению — в `evals/README.md`.

## Эксперимент с внешними отзывами

Ограниченный исследовательский pipeline сопоставляет 20 товаров с публичным
sitemap BladeRubber.net и агрегирует оценки и заранее определённые сигналы из
JSON-LD отзывов. Полные тексты отзывов не сохраняются. Публичные страницы
разрешены в `robots.txt`; запрещённые `/api/`, авторизация и URL с query string
не используются.

```bash
uv run vsitemssrag enrich-reviews
```

Результат записывается в игнорируемый Git файл
`data/exports/review_enrichment_pilot_v2.json`. Выборка содержит десять заранее
зафиксированных товаров из проблемных RAG-сценариев и десять детерминированно
выбранных товаров для оценки общего покрытия.

Использовать только подтверждённые совпадения из пилота в одном RAG-запросе:

```bash
uv run vsitemssrag ask \
  "Ищу защитное основание под длинные шипы" \
  --evidence-file data/exports/review_enrichment_pilot_v2.json
```

Для длинных шипов отдельно считаются положительный, отрицательный и
неоднозначный контексты. В текущем пилоте положительный опыт не зафиксирован.
Модель получает только качественные сигналы без чисел. После генерации код
добавляет фразы «N из M» и источники для процитированных товаров; весь итоговый
ответ проверяется на связь числа с товаром и сигналом. Остальные сигналы означают упоминание свойства,
а не доказательство пригодности.

Зафиксированный A/B-тест запускает пять сценариев по три раза для baseline и
enriched при одинаковом retrieval, system instruction и `temperature=0`.
Retrieval для всех сценариев выполняется до генераций, чтобы не держать
соединение с БД бездействующим. Между запросами Gemini выдерживается пауза
15 секунд, а checkpoint записывается после каждого ответа:

```bash
uv run python evals/run_enrichment_ab.py
```

При временном `429` команда делает дополнительные попытки. Если прогон всё же
приостановился, повторите ту же команду: готовые генерации будут пропущены.
Флаг `--restart` нужен только для намеренного запуска с нуля и перезаписывает
output. По умолчанию используются evidence-файл
`review_enrichment_pilot_v2.json` и checkpoint
`data/exports/enrichment_ab_results_v6.json`; текущий протокол —
`evals/enrichment_ab_protocol_v6.json`. Результат v5 и его аудит сохранены
отдельно в [AB_V5_AUDIT.md](docs/AB_V5_AUDIT.md). Исторический v4 сохранён отдельно. При изменении
поведения следует сохранить прежний результат и создать новую версию протокола
с отдельным output. Подробности — в [evals/README.md](evals/README.md).

Сохранённые ответы v6 можно пересчитать текущим grader без Gemini и БД,
явно указав соответствующие evidence и файлы:

```bash
uv run python evals/regrade_enrichment_ab.py \
  --input data/exports/enrichment_ab_results_v6.json \
  --evidence-file data/exports/review_enrichment_pilot_v2.json \
  --output data/exports/enrichment_ab_results_v6_regraded.json
```

Результаты и решение о масштабировании описаны в
`docs/ENRICHMENT_EXPERIMENT.md`.

TableTennisDaily был исходным кандидатом, но автоматические запросы получили
`403 Forbidden`; его защита не обходится, поэтому источник исключён из
регулярного pipeline без официального API или разрешения.

## Структура проекта

```text
.
├── data/                         # локальные генерируемые данные
│   └── exports/
├── docs/                         # проектная документация
├── src/vsitemssrag/              # устанавливаемый Python-пакет
│   ├── bot/                      # Telegram, кнопки и локальный feedback
│   ├── cli/                      # команды приложения
│   ├── scraping/                 # HTTP и разбор VistaSport
│   ├── embeddings/               # embedding-тексты и клиент Gemini
│   ├── enrichment/               # агрегаты внешних отзывов
│   ├── rag/                      # prompt, генерация, validation и grader
│   ├── storage/                  # PostgreSQL и SQL-миграции
│   ├── models.py                 # общие типы данных
│   └── settings.py               # загрузка настроек
├── tests/unit/                   # быстрые изолированные тесты
├── pyproject.toml                # метаданные и зависимости
└── uv.lock                       # точные версии зависимостей
```
