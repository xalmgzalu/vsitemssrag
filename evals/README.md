# Проверка RAG и A/B-эксперименты

Актуализировано **7 ноября 2026**. Набор `rag_cases.json` содержит пять сценариев:
новичок с бюджетом, быстрый composite, защита с длинными шипами, мягкий inner
carbon и общий запрос без критериев. Для ручной проверки используйте поле
`review` и проверяйте все фактические утверждения, а не только результат grader.

## Текущий протокол v6

`enrichment_ab_protocol_v6.json` фиксирует одинаковые retrieval, модель,
system instruction, 6 товаров, `temperature=0`, 3 повтора для каждого из
5 сценариев в baseline и enriched. Различие условий — агрегаты отзывов только
для `matched`-товаров. Запланировано 30 ответов. Общий запрос получает
детерминированный вопрос, пустой бюджетный результат — детерминированный отказ;
эти ответы не вызывают генерацию.

В v5 модель получает качественные сигналы без N и M. Код добавляет точный блок
отзывов и источники только для процитированных товаров. Статистика из самой
модели отклоняется, даже если числа случайно верны. Весь итоговый ответ
валидируется: корректная статистика не оправдывает ложные выводы рядом с ней.

Текущие версии v6: grader **7**, валидатор **7**, implementation revision **1**.
В v6 добавлены жёсткий DEF/DEF+ для long-pips и обязательный разбор мягкости.

Полный v5 revision 5 завершён (30 ответов): auto 14/15 в обоих условиях,
строгий аудит агента 10/15 baseline и 11/15 enriched. Гейт не пройден,
86 числовых evidence-фраз проверены без ошибок. Отчёт — в
[AB_V5_AUDIT.md](../docs/AB_V5_AUDIT.md). Эти оценки сохранены для версий
проверок 6 и не заменяются новыми оценками v6.

Полный v6 revision 1 завершён: auto **15/15 baseline, 14/15 enriched**;
построчный аудит агента **10/15 и 13/15**. Проверены **88** evidence-фраз,
ошибок чисел/привязки и обещаний совместимости **0**. Заданный гейт пройден,
но все метрики Vision не достигнуты: остаются сравнительные формулировки.
Из 30 ответов: 23 текста Gemini, 1 каталоговый fallback, 6 фиксированных
уточнений. Полный отчёт — в [AB_V6_AUDIT.md](../docs/AB_V6_AUDIT.md).

## История отладки v5

В первом частичном запуске валидатор ошибочно принимал цифру в названии V3 за
статистику отзывов. Его checkpoint сохранён отдельно как
`data/exports/enrichment_ab_results_v5_attempt1.json`; он не включается в чистый
повтор v5. Второй частичный запуск (12 ответов) сохранён как
`enrichment_ab_results_v5_attempt2.json`: исправлены ложное отклонение
отрицания подтверждения совместимости и пропуск превосходной степени скорости.
Третий частичный запуск (14 ответов) сохранён как
`enrichment_ab_results_v5_attempt3.json`: уточнены отрицания со словом
«совместимость» и распознавание синонима «сопоставлять» в grader.
Четвёртая частичная попытка (13 ответов) сохранена как
`enrichment_ab_results_v5_attempt4.json`: модель трижды повторила реальное
неподтверждённое заявление о пригодности под длинные шипы. Чистый revision 5
добавляет после исчерпания попыток безопасный каталоговый ответ с отдельным
`answer_origin=deterministic_catalog_fallback`. Его доля учитывается отдельно
и не скрывается внутри метрики успешных генераций модели. Исторический протокол
v4 остаётся в `enrichment_ab_protocol.json`.

## Запуск и продолжение

Команда использует `.env` с `GEMINI_API_KEY` и `DATABASE_URL`:

```bash
uv run python evals/run_enrichment_ab.py \
  --protocol evals/enrichment_ab_protocol_v6.json \
  --output data/exports/enrichment_ab_results_v6.json
```

Protocol v6 и output v6 являются значениями по умолчанию. v5 и его аудит
остаются отдельными неизменными файлами.
Evidence по умолчанию — `data/exports/review_enrichment_pilot_v2.json`.

Retrieval выполняется до генераций, соединение с БД затем закрывается. Между
генерациями и исправляющими попытками выдерживается пауза 15 секунд; временные
ошибки API повторяются. Готовые ответы атомарно сохраняются после каждого шага.
При совпадении конфигурации повтор команды продолжает checkpoint. Проверяются
модель, параметры, версии проверок и хеши prompt, протокола, кейсов и evidence.
Не пересоздавайте evidence перед продолжением: это изменит хеш.

При несовпадении конфигурации runner отказывается продолжать. `--restart`
перезаписывает выбранный output; для изменённого поведения сначала сохраните
исходный checkpoint и зафиксируйте новую ревизию протокола/отдельный output.
Не смешивайте ответы разных версий. `--case ID` подходит для диагностики,
но не заменяет полный прогон.

## Диагностика

Общий advisor делает до трёх попыток получить прошедший validation ответ.
Каждый отклонённый ответ записывается в
`data/exports/rag_validation_rejections.jsonl`: время UTC, вопрос, номер попытки,
исходный ответ модели, собранный итоговый ответ и точные ошибки проверки.
Лог локальный и исключён из Git. Тесты отклонений используют временные файлы.

После трёх отклонений advisor пробует безопасный резервный ответ: только
каталожные поля и точные агрегаты, с повторной валидацией. В нём нет текста
отклонённой генерации. Если и он отклонён либо закончились повторы API, runner
сохраняет `status=paused` и `last_error`, затем завершает работу с кодом 1. Отклонённый ответ не засчитывается как сохранённый
успешный ответ; его можно изучить в JSONL-логе.

## Пересчёт без генераций и БД

```bash
uv run python evals/regrade_enrichment_ab.py \
  --input data/exports/enrichment_ab_results_v6.json \
  --evidence-file data/exports/review_enrichment_pilot_v2.json \
  --output data/exports/enrichment_ab_results_v6_regraded.json
```

Передавайте evidence именно из конфигурации исходного прогона. Значения по
умолчанию у regrade по-прежнему относятся к исходному эксперименту: файлам
`enrichment_ab_results.json`, `review_enrichment_pilot.json` и
`enrichment_ab_results_regraded.json`. Пересчёт не заполняет недостающие ответы
и не завершает приостановленный прогон. Старые результаты могут получить другие
оценки при новом grader; исходные файлы следует сохранять.

## Критерий завершения

Завершение реализации TASK-1/TASK-2 и завершение эксперимента — разные события.
Для гейта качества нужны полный прогон соответствующей версии (30 ответов),
строгий аудит всех ответов,
не менее **12/15 enriched**, ноль ошибок чисел и привязки evidence, ноль
неподтверждённых заявлений о совместимости. Автоматическая оценка не заменяет
аудит; высокий pass rate неполного прогона не подтверждает готовность.

LLM-as-a-judge в runner не используется. Лексические проверки ограничены;
результаты аудита должны указывать проверяющего и отсутствие независимости,
если аудит выполняет тот же агент, который менял код.

[ENRICHMENT_EXPERIMENT.md](../docs/ENRICHMENT_EXPERIMENT.md), состояние задач —
в [CURRENT_STATE.md](../docs/CURRENT_STATE.md) и
